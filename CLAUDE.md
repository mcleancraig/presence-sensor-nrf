# presence-sensor-nrf

BTHome v2 BLE mmWave human presence, motion, distance, and battery sensor on a SuperMini nRF52840 (`nice!nano v2` clone) + Hi-Link HLK-LD2410S 24 GHz radar, NCS v2.8.0.

**Read `doc/bringup-notes.md` before changing the flash layout, power config, UART runtime PM, battery sensing, or enclosure geometry.** Key invariants:

- **Bootloader & Flash Offset (`0x1000`)**: The SuperMini's Adafruit UF2 bootloader (`0.6.1_nosd`) has **no SoftDevice** and jumps to `0x1000` (`MBR_SIZE`), not `0x26000`. `boards/nicekeyboards/nice_nano/nice_nano.dts` places `code_partition` at `0x1000`. New boards on `0.6.0` should be updated with `update-nice_nano_bootloader-0.6.1_nosd.uf2` first.
- **Continuous Radar Power (`P0.13` HIGH)**: Unlike the BH1750 light sensor, the HLK-LD2410S **must remain continuously powered** on the switched 3.3 V `VCC` rail (`P0.13` HIGH, `power-cutoff-gpios`) so its internal 1 Hz low-speed FMCW state machine (`~58–100 µA`) and background noise adaptation stay alive, and so its `3.0–3.6 V` input rating is protected from raw Li-ion voltages (`4.2 V`). `P0.13` is driven LOW only on confirmed `<= 3.0 V` battery cutoff in `BatteryMonitor::ReadBatteryStatus()` before `sys_poweroff()`.
- **`uart0` Runtime PM (`PM_DEVICE_ACTION_SUSPEND`) & Interrupt-Driven RX (`CONFIG_UART_INTERRUPT_DRIVEN=y`)**: `uart0` (`P0.08` / `008` / `D0` RX <- Radar `OT1`, `P0.06` / `006` / `D1` TX -> Radar `RX`, `115200` baud) uses interrupt-driven RX with a 256-byte ISR ring buffer (`SensorLd2410s::OnUartIsr`) for HLK-LD2410S configuration (`CONFIG_APP_RADAR_MAX_GATE=3` / `2.10 m`, `CONFIG_APP_RADAR_MIN_GATE=0`, `CONFIG_APP_RADAR_HOLD_S=30`) and distance reads (`CONFIG_APP_OCCUPIED_DISTANCE_POLL_SEC=5`). Leaving `UARTE0` enabled in idle drains `~500 µA` (keeps 64 MHz HFCLK + EasyDMA running). `SensorLd2410s` suspends `uart0` via `pm_device_action_run(..., PM_DEVICE_ACTION_SUSPEND)` after boot config and wraps every subsequent UART read (`kDefaultSampleTimeoutMs = 1150`) in an RAII `ScopedUartWake` (`PM_DEVICE_ACTION_RESUME` + `uart_irq_rx_enable` -> read -> `uart_irq_rx_disable` + `PM_DEVICE_ACTION_SUSPEND`).
- **Wake Interrupt (`P0.17` `OT2`)**: HLK-LD2410S `OT2` drives `P0.17` (`017` / `D2`, `GPIO_INT_EDGE_BOTH`), waking the nRF52840 from System ON Idle immediately on occupancy entry/exit.
- **BTHome v2 (`0xFCD2`)**: Non-connectable, scannable BLE advertisements (`CONFIG_BT_BROADCASTER=y`, `CONFIG_BT_EXT_ADV=n`). Object IDs must remain in strict ascending order (`0x00` packet ID, `0x01` battery %, `0x0C` voltage V, `0x21` motion, `0x23` occupancy, `0x40` distance mm). Note that `0x23` is `occupancy` (`Clear` / `Detected` in Home Assistant), whereas `0x2D` is `window` (`Closed` / `Open`). Primary ADV PDU is 22 bytes (`<= 31 B` limit); Scan Response carries `Presence-XXXX` (folded 16-bit FNV-1a hash of `hwinfo_get_device_id()` via `BthomeProto::DeriveShortIdFromDeviceId()`).
- **Host Unit Tests**: Run `scripts/run-tests.sh` before every commit to verify HLK-LD2410S frame parsing (including distance bytes colliding with `0x6E`/`0x62` delimiters) and BTHome v2 byte-exact encoding.
- **Builds**: Local build via `source env.sh && west build --no-sysbuild -b nice_nano/nrf52840 -s ~/git/presence-sensor-nrf -d ~/git/presence-sensor-nrf/build -- -DBOARD_ROOT=$HOME/git/presence-sensor-nrf` (append `-DEXTRA_CONF_FILE="local.conf;ld2410c.conf"` for the HLK-LD2410C variant), or fetch CI artifacts with `scripts/fetch-firmware.sh [--ld2410c] [--debug]`.
- **Debug Build**: Append `-DEXTRA_CONF_FILE=debug.conf -DEXTRA_DTC_OVERLAY_FILE=debug.overlay` for USB CDC ACM logging (`/dev/cu.usbmodem*`); release builds must have `CONFIG_LOG=n` and `CONFIG_CONSOLE=n`.
- **Enclosures (4 Bambu A1 Models) & Radar Mechanical Specs (`20.0 × 20.0 × 1.2 mm` HLK-LD2410S & `22.0 × 16.0 × 1.2 mm` HLK-LD2410C)**: Parametric CadQuery generators in `enclosure/enclosure.py` and `enclosure/enclosure_variants.py` build 4 support-free variants verified by `enclosure/verify.py` and `enclosure/sections.py`:
  1. **Model 1 (`base.stl` + `lid.stl` / `base.step` + `lid.step` + `assembly.step`)**: Sealed Gasketed Wall-Mount Enclosure for HLK-LD2410S (M3×5.7 heat-set inserts + 2 mm EPDM/TPU gasket groove + wall-mount tabs).
  2. **Model 2 (`corner_base.stl` + `corner_lid.stl` + `corner_bracket.stl` / `.step` + `corner_assembly.step`)**: Compact Snap-Fit Enclosure with 45° Downward-Tilt 90° Room-Corner / Ceiling Bracket for HLK-LD2410S.
  3. **Model 3 (`vanity_base.stl` + `vanity_lid.stl` / `.step` + `vanity_assembly.step`)**: Freestanding Shelf/Vanity Pod with USB-C Pass-Through for HLK-LD2410S.
  4. **Model 4 (`ld2410c_base.stl` + `ld2410c_lid.stl` / `.step` + `ld2410c_assembly.step` + `ld2410c_fit_check.step`)**: Constant USB-C Power Enclosure for the **`22.0 × 16.0 × 1.2 mm` HLK-LD2410C** (`24 × 18 × 1.2 mm` blind RF radome pocket, centered `+X` 5-pin DuPont exit channel, `+X` USB-C pass-through slot + cable overmold counterbore, flat `-Y` shelf foot, and `±X` wall-mount screw tabs).
  The HLK-LD2410S is a **`20.0 × 20.0 × 1.2 mm` square PCB** with `R = 2.0 mm` rounded corners and a **`2.54 mm` (`0.100"`) pitch** 5-pin `J2` header (`3V3`, `GND`, `OT1`, `RX`, `OT2`) asymmetrically positioned along its `+X` edge (`Pin 5 OT2` at `1.62 mm` from top `+Y` edge down to `Pin 1 3V3` at `11.78 mm` from top `+Y` edge; hole centers `1.47 mm` inward from `+X` edge). Mount with the antenna side (`TOP层`, two diagonally opposite 24 GHz patch antennas + `ICL1112` transceiver IC) facing **UP (`+Z`)** toward the lid's `22 × 22 × 1.2 mm` blind RF radome window, and the component/header side (`Bottom层`, `PY32F030` MCU, `YXC` crystal, `-Z` 5-pin `J2` header) facing **DOWN (`-Z`)** with `19.5 mm` of under-board vertical clearance and `J2` facing **`+X` toward the SuperMini nRF52840** (optional `10–47 µF` decoupling capacitor solders directly across adjacent `Pin 1 3V3` and `Pin 2 GND` on `-Z`).
